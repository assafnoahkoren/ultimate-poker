# Ultimate Texas Hold'em — Monte Carlo Simulator (Go)

## Context

Greenfield project. The goal is a headless Go simulator for Ultimate Texas Hold'em (UTH), the Bally/Bovada cardroom game described in the CA AG rules PDF. We want to:

- Simulate millions–billions of hands to measure house edge, EV, fold rates, and hand-frequency distributions.
- Plug in arbitrary decision strategies (random, always-check, optimal, custom) without touching the engine.
- Support all four published paytable variants (UTH-01 through UTH-04).
- Run in parallel across cores; produce a one-screen text report (or JSON).

No UI, no networking, no real-money concerns — a research tool. Go was chosen for fast iteration, trivial goroutine parallelism, and adequate throughput (~20M hands/sec on a modern laptop with the chosen evaluator). Strategy is a pluggable interface so an optimal-play implementation can be added later without changing anything else.

## Component-by-component design

### 1. `cards` — card + deck

- `type Card uint8` with values 0..51; `rank = c/4`, `suit = c%4`. Ranks 0..12 = 2..A.
- `type Deck [52]Card` with `Shuffle(rng *rand.Rand)` doing Fisher-Yates in place. Zero allocations.
- RNG: `math/rand/v2` PCG, one per worker, seeded `cfgSeed ^ workerID`. Do **not** use `crypto/rand` or the global rand.

### 2. `eval` — 7-card hand evaluator

**Approach: Cactus Kev 5-card evaluator + 21-iteration loop over C(7,5).**

- Returns Cactus Kev `int32` rank (lower = better).
- Returns `HandCategory` (HighCard..RoyalFlush) bucketed from the rank.
- ~200–300 ns per 7-card eval → ~2.5M hands/sec/core × 8 cores ≈ 20M hands/sec; 10⁹ hands in under a minute on an M-series laptop.
- Tables (~15 KB total) generated by `internal/eval/gen/main.go` and committed as Go literals or `//go:embed`. No runtime init cost.

Rejected alternatives:
- 2+2 lookup (~123 MB asset): faster, but the embedded asset is gross for a side project.
- Senzee 7-card (~32 MB): fiddly to port; not worth the dev cost.
- Naive 21-combo classifier: simpler than Cactus Kev but ~10× slower and not actually shorter to write correctly.

### 3. `paytables` — variant definitions

```go
type Ratio struct{ Num, Den int32 }      // 3:2 → {3,2}, 1:1 → {1,1}
type BlindPayout struct { Royal, StraightFlush, Quads, FullHouse, Flush, Straight Ratio }
type TripsPayout struct { Royal, StraightFlush, Quads, FullHouse, Flush, Straight, Trips Ratio }
type Variant struct {
    ID    string
    Blind BlindPayout
    Trips TripsPayout
}
var UTH01, UTH02, UTH03, UTH04 Variant   // populated from PDF table
func ByID(id string) (Variant, error)
```

Struct-of-fields, not a map — no allocations, cache-friendly. Variant selected once at startup.

### 4. `game` — hand state machine + settlement

```go
type Outcome struct {
    AnteNet, BlindNet, PlayNet, TripsNet int64       // chip deltas
    PlayerCategory, DealerCategory       eval.HandCategory
    Folded                               bool
    DealerQualified                      bool
}

func PlayHand(
    deck   *cards.Deck,            // pre-shuffled
    strat  strategy.Strategy,
    pt     paytables.Variant,
    ante   int64,
    placedTrips bool,
) Outcome
```

Internally:
1. Deal 2 player hole + 2 dealer hole + 5 board (consume top 9 of shuffled deck).
2. Strategy callback pre-flop → if bet 3x or 4x, jump to showdown; else continue.
3. Strategy callback post-flop with board[0..2] → if bet 2x, jump to showdown; else continue.
4. Strategy callback post-river with all 5 board cards → fold or bet 1x.
5. Settle: pure function `Settle(player7, dealer7 [7]Card, playMult, ante int64, folded, placedTrips bool, pt Variant) Outcome`.

Settlement rules (encoded once, table-driven test):
- Folded → lose Ante + Blind; Play = 0; Trips still pays from player7 if 3oak+.
- Else evaluate both 7-card hands.
- Dealer qualified iff dealer category ≥ Pair.
- Compare ranks:
  - Player wins: Ante 1:1 (push if dealer didn't qualify); Play 1:1; Blind pays from BlindPayout if player category ≥ Straight, else pushes.
  - Player loses: Ante/Blind/Play all lost.
  - Tie: all push.
- Trips: pays from TripsPayout if player category ≥ ThreeOfAKind, regardless of win/lose/fold/push; otherwise lost.

Uses a stack `[9]Card` slice from the deck — zero per-hand allocations.

### 5. `strategy` — pluggable decision interface

```go
type PreFlopAction uint8 // Check, Bet3x, Bet4x
type FlopAction    uint8 // Check, Bet2x
type RiverAction   uint8 // Fold, Bet1x

type Context struct {
    Ante int64
    Hand uint64        // hand index, useful for stateful strats
}

type Strategy interface {
    Name() string
    PreFlop(ctx Context, hole [2]cards.Card)                          PreFlopAction
    Flop   (ctx Context, hole [2]cards.Card, flop  [3]cards.Card)     FlopAction
    River  (ctx Context, hole [2]cards.Card, board [5]cards.Card)     RiverAction
}

type Factory func() Strategy   // one Strategy per worker — enables stateful strats without locks
```

Deliberately does **not** receive bankroll/history: UTH decisions are EV-independent of those, and passing them bloats the hot loop. Wrap the runner if you want martingale-style sims.

Ship three baselines:
- `always_check.go` — Check, Check, Bet1x (never folds at river). Cheapest baseline; sets the ceiling for "passive" play.
- `always_4x.go` — Bet4x pre-flop always. Tests the cost of maximum-aggression.
- `random.go` — uniform-random over legal actions. Sanity baseline.

(Optimal strategy can be added later as another file — no engine changes needed.)

### 6. `sim` — parallel runner

```go
type Config struct {
    Hands    uint64
    Workers  int                  // default runtime.NumCPU()
    Variant  paytables.Variant
    Factory  strategy.Factory
    Seed     uint64
    AnteUnit int64                // typically 1
    Trips    bool                 // whether to place the optional Trips wager
}

type Stats struct {
    Hands              uint64
    AnteNet, BlindNet  int64
    PlayNet, TripsNet  int64
    CategoryCounts     [10]uint64   // by player final category
    DealerQualified    uint64
    Folds              uint64
}
func (s *Stats) Merge(o *Stats)

func Run(cfg Config) (Stats, time.Duration)
```

Worker loop (one goroutine per worker):
- Own RNG (`rand.New(rand.NewPCG(seed, uint64(workerID)))`).
- Own `Strategy` from `cfg.Factory()`.
- Own `Stats`, own `Deck`.
- Repeat `hands/workers` iterations: shuffle deck, `PlayHand`, fold outcome into local stats.
- Send `*Stats` on a result channel.

Main goroutine merges all worker stats. Sharded-then-merged beats atomics because atomic counters serialize cores via cache-line ping-pong; per-worker structs stay in L1.

Progress: a single shared `atomic.Uint64` that workers bump every 10,000 hands; ticker goroutine reads it and prints. Out of the hot loop.

### 8. Testing strategy

- **`eval` golden enumeration** — opt-in via `go test -tags=golden`. Enumerate all C(52,7) = 133,784,560 hands, assert category counts match published values (e.g., 4,324 royal flushes, 37,260 straight flushes, …). Definitive evaluator correctness check; takes ~30–60s — too slow for default CI, perfect as a manual gate.
- **`eval` spot tests** — handful of crafted 7-card hands → expected (category, relative rank order). Runs in milliseconds.
- **`game` settlement tests** — table-driven over `(playerCat, dealerCat, dealerQual, folded, playMult, placedTrips)` → expected net. ~30 rows covers the rule matrix from the PDF.
- **`strategy` dispatch tests** — trivial; verify each baseline returns the expected action.
- **`sim` determinism test** — same seed + `workers=1` → bit-identical stats. (Multi-worker is non-deterministic unless hand ranges are pre-assigned; that's a deliberate trade-off and documented.)
- **`sim` smoke test** — 1M hands of `always-check` vs UTH-01 → house edge within ±0.2% of published ~2.19% on Ante+Blind. Wide tolerance.

Skip: evaluator fuzzing (the full enumeration is strictly stronger), per-strategy microbenchmarks (the whole runner is the benchmark).

## Build order

1. `cards` — Card, Deck, RNG. ~30 lines.
2. `eval` — Cactus Kev port + generator + tables + 7-card wrapper + spot tests.
3. `eval` golden enumeration test — gate everything else on this passing.
4. `paytables` — types + the four variants from the PDF table.
5. `game` — settle.go (pure function, fully unit-testable) → hand.go orchestrator.
6. `strategy` — interface + three baselines.
7. `sim` — single-threaded runner first; verify smoke test; then parallelize.
8. `cmd/uthsim` — flags, wiring, text + JSON report.

Each step ships behind tests, no leapfrogging.

## Verification

End-to-end check after step 8:

```bash
go test ./...                                    # all unit tests
go test -tags=golden ./internal/eval/...         # full enumeration
go run ./cmd/uthsim --variant UTH-01 --strategy always-check --hands 1000000 --seed 1
# Expect: house edge Ante+Blind within ±0.2% of 2.19%; fold rate ~0% (always-check never folds).

go run ./cmd/uthsim --variant UTH-01 --strategy always-4x --hands 10000000 --seed 1
# Expect: lower house edge than always-check (closer to optimal ~2.19% lower bound).

go run ./cmd/uthsim --variant UTH-01 --strategy random --hands 1000000 --seed 1
# Expect: much higher house edge (random play is bad).
```

Cross-check Trips house edge against the published ~6.18% (UTH-01) within ±0.05% over 100M hands.
